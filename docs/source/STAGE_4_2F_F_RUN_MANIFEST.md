## Queue — `PRODUCTION_QUEUE_v5`

v5 is produced by the run2 engine with its K2 model advanced to the binary-measured 4.2F-F
model. The nine K2 rows are **read back from the emitted artifacts**; every non-K2 row is
regenerated from source and proven identical to the pre-advance baseline. Because the
non-K2 rows come from the engine (not from the retired v4 file), **Queue v5 reproduces
byte-identically from the committed Stage-F artifacts alone — the retired `PRODUCTION_QUEUE_v4`
is not required** (verified by rebuilding with v4 absent). The retired v4 file, when still
present, is used only as an extra transition check.

Two reproducibility scopes must not be conflated:

- **Queue v5** — reproduces from committed Stage-F artifacts (the K2 model, the emitted
  hierarchy/models/assessment JSON, and the run2 engine over the committed K3/K5/PL06
  source), **without** the retired Queue v4 and **without** re-reading the binary.
- **Full raw extraction and regeneration** — rebuilding `K2_EXTRACTION_EVIDENCE_v1.json`
  from scratch (per-page text, PL spans, image/table counts, the live SHA-256) **requires
  the verified K2 binary to be supplied locally at the documented path**
  `.source-intake/K2/2. PENGURUSAN PEMBINAAN LANDASAN.pdf` (25,043,306 bytes, SHA-256
  `0b2d81dd…f405680`). That binary is git-ignored via `.git/info/exclude` and is not in the
  commit, so it must be placed at that path before `src_k2f_extract_v1.py` can re-measure.
  The frozen evidence file *is* committed, so every downstream artifact and every QA gate is
  checkable without the binary; only re-measuring from the bytes needs it present at the
  path above.

No queue field was added or redesigned: the requirements are enforced through the
distinctions the schema already draws —

- **record_type** — stays `CANDIDATE_STRUCTURE` for all nine; no storyboard granularity is
  independently confirmed;
- **processing state** — `extraction_status` + `model_status` (+ the boolean state flags),
  advanced per row only as far as its own artifacts support;
- **blocker** — `exact_blocker` + `blocker_owner`, where PL06 and PL08 carry the KT06
  exception (tagged with the stable `K2-SOURCE-OBS-03` token) with their distinct
  consequences;
- **authority readiness** — `authority_dependency` + `immediately_executable`.
